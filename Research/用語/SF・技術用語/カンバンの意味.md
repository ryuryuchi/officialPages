# カンバンの意味

## 概要

タスク管理アプリのUIで使われる「カンバン」または「カンバンボード」が、どのような見た目と仕組みを指すのかを整理する。

## 結論

カンバンは、タスクを**カード**として表し、進捗段階ごとの**列（カラム）**に並べて管理するボード型のUIである。典型的には、次のような横並びになる。

```text
┌────────────┐  ┌────────────┐  ┌────────────┐
│ 未着手      │  │ 進行中      │  │ 完了        │
│ To Do      │  │ In Progress│  │ Done       │
├────────────┤  ├────────────┤  ├────────────┤
│ タスクA     │  │ タスクC     │  │ タスクD     │
│ タスクB     │  │             │  │             │
└────────────┘  └────────────┘  └────────────┘
```

タスクのカードをドラッグ＆ドロップで別の列へ移動すると、状態も「未着手」から「進行中」のように更新される。つまり、一覧表で状態を文字入力するよりも、**作業の流れと滞留箇所を画面上で直感的に把握する**ための形である。

## 詳細

### UIを構成する要素

| 要素 | 役割 |
| --- | --- |
| ボード | 1つのプロジェクト、チーム、業務フロー全体を表示する領域 |
| 列（カラム） | タスクの状態や工程を表す。「未着手」「進行中」「レビュー」「完了」など |
| カード | 1件のタスク。タイトル、担当者、期限、ラベル、チェックリストなどを表示する |
| 移動操作 | カードを列から列へ移動し、タスクの状態を変更する |

### よくある列の例

最小構成は「To Do」「In Progress」「Done」の3列である。実際の業務では、次のように工程を細かく分けることもある。

```text
アイデア → 未着手 → 作業中 → レビュー待ち → 完了
```

列は固定の正解があるわけではなく、作業の流れに合わせて設計する。例えばソフトウェア開発なら「要件確認」「実装中」「テスト中」「リリース済み」といった列にできる。

### リスト形式との違い

リスト形式はタスクを縦に並べるのに対し、カンバンは状態や工程を横方向の列で分ける。そのため、次の点を把握しやすい。

- どのタスクが未着手、進行中、完了なのか
- 特定の工程にタスクが集中していないか
- チーム内で誰が何を担当しているか
- 作業がどこで止まっているか

### WIP制限との関係

カンバンでは、進行中（Work In Progress、WIP）のカード数に上限を設けることがある。進行中の仕事を増やしすぎず、作業の滞留やボトルネックを見つけやすくするためである。ただし、タスク管理アプリでカンバン表示ができることと、WIP制限を必ず運用することは別である。

### UIとして見るときの注意点

- 列は「状態」だけでなく「担当チーム」や「工程」を表す場合があるため、列名を確認する。
- カードを移動できても、実際の保存タイミングや権限はアプリごとに異なる。
- 列が多すぎると全体像を把握しにくくなるため、最初は3〜5列程度にすると分かりやすい。
- カンバンは進捗を見える化する画面であり、期限、優先度、依存関係などを完全に置き換えるものではない。
