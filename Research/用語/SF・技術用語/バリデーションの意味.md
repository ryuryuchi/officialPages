# バリデーションの意味

## 概要

「バリデーション（validation）」という言葉の一般的な意味と、ソフトウェア開発でよく使われる入力バリデーションの意味を整理する。

## 結論

**バリデーション**は、対象があらかじめ決めた条件・目的・要件に対して妥当かを確かめることを指し、日本語では文脈に応じて「妥当性確認」「妥当性検証」「検証」などと訳される。

ソフトウェア開発で「バリデーション」とだけ言う場合は、通常、**入力された値が受け付けてよい条件を満たすか確認する入力チェック**を意味する。例えば、メールアドレスの形式、必須項目、文字数、数値の範囲、開始日と終了日の前後関係を確認する。

## 詳細

### 言葉の基本的な意味

`validation` は、何かを無条件に「正しい」と認定することではない。先に定めた基準に照らして、対象が目的に合うか、受け入れてよいかを確認する行為である。

基準は分野によって異なる。

| 分野 | バリデーションの対象・基準の例 |
| --- | --- |
| ソフトウェア | 入力値が形式・範囲・業務ルールを満たすか |
| データ分析 | データやモデルが想定した用途で使える品質か |
| 製造・医療 | 工程や装置が意図した結果を継続して出せるか |
| 申請・フォーム | 必須情報がそろい、申請条件を満たすか |

したがって、「何を」「どの条件に対して」確認するのかがないと、バリデーションの具体的な内容は決まらない。

### ソフトウェアにおける入力バリデーション

入力バリデーションは、ユーザー、外部API、ファイル、他システムなどから受け取ったデータを、処理や保存の前に確認することである。OWASPは、情報システムの処理へ適切な形式のデータだけを入れ、不正な形式のデータが保存されたり後続処理の不具合を起こしたりすることを防ぐ目的を示している。

主な確認には、次の2種類がある。

| 種類 | 確認すること | 例 |
| --- | --- | --- |
| 構文の確認 | データ形式が正しいか | 郵便番号が数字とハイフンで構成される、日付が日付として読める |
| 意味・業務ルールの確認 | その値が利用目的に照らして妥当か | 開始日が終了日より前、年齢が利用可能な範囲、選択値が許可一覧に含まれる |

例えば、`2026-02-31` は日付らしい文字の並びでも、実在しない日付なので受け付けない、という確認もバリデーションである。

### よくあるチェック例

- 必須項目が空でないか
- 文字数が最小・最大の範囲内か
- 数値や日付として読み取れるか
- 数値が許可された範囲内か
- メールアドレス、電話番号、郵便番号などの形式に合うか
- パスワード確認欄が元のパスワードと一致するか
- 選択肢にない値が送られていないか
- 複数項目の関係が業務ルールに合うか

### セキュリティ上の注意

画面側で入力欄を制限していても、通信を直接変更して不正な値を送ることはできる。そのため、重要なバリデーションは画面側だけで完結させず、データを受け取るサーバー側でも行う必要がある。

また、バリデーションは安全対策の一部であり、SQLインジェクションやクロスサイトスクリプティング対策をこれだけで置き換えるものではない。OWASPは、入力バリデーションをこれらの攻撃を防ぐ主たる手段にしてはならないとしている。用途に応じて、パラメーター化クエリや出力時のエスケープなども併用する。

### 「検証」との使い分け

日本語ではバリデーションを単に「検証」と訳すことが多い。一方で、開発・品質保証の文脈では、`verification` と `validation` を区別する場合がある。

- **verification（ベリフィケーション）**: 設計書・仕様書など、定めた要求どおりに作られているかを確認する
- **validation（バリデーション）**: 実際の利用目的や利用者の必要を満たせるかを確認する

ただし、組織・規格・製品ごとに用語の定義が異なるため、仕様書や規程に定義がある場合はその定義を優先する。

### 短く言うと

> バリデーションは、「そのデータや仕組みを受け付けてよいか」を決めた条件に照らして確かめること。  
> プログラムでは特に、「入力内容がルールに合っているかのチェック」を指す。
