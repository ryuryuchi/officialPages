# Copilot Chatで最初に試すコマンド

## 概要

Visual Studio Code（VS Code）のGitHub Copilot Chatで使えるスラッシュコマンドから、
初めて触るときに効果を理解しやすいものを選び、用途と入力例を整理する。

## 結論

最初は次の5つがおすすめである。上から順に試すと、理解、修正、テスト作成、
会話の整理という基本的な流れを体験しやすい。

| おすすめ順 | コマンド | 用途 |
| --- | --- | --- |
| 1 | `/explain` | コード、ファイル、プログラミング概念を説明してもらう |
| 2 | `/fix` | コードやコンパイラー・lintエラーの修正を依頼する |
| 3 | `/tests` | 対象のメソッドや関数のテストを生成する |
| 4 | `/compact` | 長い会話を要約してコンテキストを圧縮する |
| 5 | `/clear` | Chat viewで新しいチャットセッションを開始する |

これは初心者向けの選定であり、公式の推奨順位ではない。実際に使えるコマンドは
環境やチャットのコンテキストによって異なるため、チャット入力欄に `/` と入力して
表示される一覧を正とする。

## 詳細

### 基本的な使い方

1. VS Codeでチャットビューを開く。
2. 入力欄に `/` を入力し、候補からコマンドを選ぶ。
3. 必要に応じてコードを選択するか、対象を文章で補足して送信する。
4. コード変更が提案された場合は、差分を確認してから採用する。

### 1. `/explain`

アクティブなエディターのコードがどのように機能するか説明してもらう。知らない
コードを読むときや、処理の流れを確認するときに使いやすい。

```text
/explain この関数を初心者向けに説明して
```

質問を「何を入力として受け取り、何を返すか」のように具体化すると、確認したい点に
絞った回答を得やすい。

### 2. `/fix`

選択したコードの問題に対する修正を提案してもらう。エラーが出ている箇所や、
期待どおり動かない範囲を選択して使う。

```text
/fix このエラーの原因も説明して
```

提案は必ず正しいとは限らない。変更差分を読み、既存のテストがある場合は実行して
確認する。

### 3. `/tests`

選択したコードに対する単体テストを生成してもらう。正常系だけでなく、空文字、
境界値、エラーなども含めるよう補足すると用途が分かりやすい。

```text
/tests 正常系と境界値のテストを作成して
```

生成されたテストがプロジェクト既存のテストフレームワークや書き方に合っているかを
確認する必要がある。

### 4. `/compact`

長くなった会話の過去部分を要約し、コンテキストウィンドウの空きを増やす。
新しいセッションにはせず、現在の会話の重要事項を残したまま継続したいときに使う。
残す内容を後ろへ指定できる。

```text
/compact API設計の決定事項を残して
```

### 5. `/clear`

新しいチャットセッションを開始する。前の話題の影響を避けて、別の質問を始めたい
ときに使う。

```text
/clear
```

### 次に試す候補

- `/fixTestFailure`: 失敗したテストを見つけて修正する。テスト実行まで扱うように
  なってから試す候補。環境によってはコマンドではなくTestingのスマートアクション
  として表示される。
- `/new`: 新しいプロジェクトを作成する。ファイル変更を伴うため、最初の練習では
  作業用フォルダーを用意してから使う。
- `/rubber-duck`: Copilot Agent Hostセッションで別モデルに計画や実装を
  批評させる機能。VS Code 1.135では実験的で、単純な質問より、
  複雑な作業の見落とし確認に向く。詳細は
  [GitHub CopilotのRubber Duck機能](./GitHub%20CopilotのRubber%20Duck機能.md)
  を参照する。

### コマンドと対象指定の違い

`/` はよく使う処理を呼び出すスラッシュコマンドである。一方、`#` は回答に含める
対象やコンテキストを明示するために使う。たとえば、ファイル名やフォルダー名を
`#`に続けて指定でき、`#selection`は現在選択しているテキストを対象に含める。

```text
/explain #selection
```

VS Codeはアクティブなファイルや選択範囲を暗黙のコンテキストとして含める場合が
あるが、対象が曖昧なときは `#` による指定を併用すると意図を伝えやすい。
