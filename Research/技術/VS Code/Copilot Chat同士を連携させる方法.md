# Copilot Chat同士を連携させる方法

## 概要

VS CodeのGitHub Copilotで、複数のCopilot Chatやエージェントセッションが
互いに通信、情報共有、並行作業できるかを調査した。独立セッション、
同一セッション内の複数チャット、サブエージェント、共有ファイルによる連携を
区別して整理する。

## 結論

**方法はある。** 2026年8月31日時点のVS Code Agent Hostでは、エージェントが
セッション一覧の取得、新しいセッションまたはチャットの作成、別セッションの
最近のコンテキストの参照、セッション間の追加メッセージ送信を行える。

ただし、すべてのCopilot Chatが自動的に会話履歴を共有するわけではない。
基本単位であるセッションは独立しており、同一セッション内の複数チャットも、
ワークスペースとworktreeは共有するが会話履歴は別である。連携させるには、
Agent Hostのセッション操作、親エージェントからサブエージェントへの委譲、
またはファイルやIssueなどの共有媒体を明示的に使う必要がある。

現在のCopilot Agent Host環境で実用的なのは、メインチャットへ
「別チャットを作って調査を依頼し、結果を読み取ってこちらへ統合して」のように
依頼する方法である。単に複数チャットを開くだけでは相互通信しない。
VS Code 1.135では、Copilot CLI、GitHub Copilot app、Claude Code、Codexで作成した
対応ローカルセッションを発見し、VS Codeへ引き継ぐ機能も追加されている。

## 詳細

### 連携方法の比較

| 方法 | 会話履歴 | コード作業場所 | 主な連携経路 | 向いている用途 |
| --- | --- | --- | --- | --- |
| Agent Hostのセッション間連携 | セッションごとに独立 | 設定したworkspaceまたはworktree | 一覧取得、作成、コンテキスト参照、メッセージ送信 | 独立したChat同士の明示的な協調 |
| 同一セッション内の複数チャット | チャットごとに独立 | 同じworkspaceとworktreeを共有 | 共有ファイル、明示的なメッセージやコンテキスト取得 | 同じプロジェクトの並行作業 |
| セッションまたはチャットのfork | 分岐地点まで引き継ぐ | 元の設定を基に分岐 | 分岐時に履歴を複製 | 別案の比較、試行 |
| 親エージェントとサブエージェント | サブエージェントは独立したコンテキスト | 親から割り当てられた範囲 | 親が委譲し、結果を受け取る | 調査、レビュー、テストの分担 |
| `AGENTS.md`や共有ファイル | 共有しない | 同じファイルを参照可能 | Git管理ファイルを仲介 | 共通ルール、進捗、成果物の共有 |

### Agent Hostによるセッション間連携

VS Code公式ドキュメントは、Agent Host上のエージェントが次の操作を行えると
明記している。

- セッションを一覧表示する
- 新しいセッションまたはチャットを作成する
- 別セッションの最近のコンテキストを読む
- セッション間で追加メッセージを送る

この仕組みなら、メインチャットをオーケストレーターとして、調査用、実装用、
レビュー用のチャットを作り、それぞれの結果を回収して統合できる。
Agent Hostで利用できる操作は`list_sessions`、`create_session`、`create_chat`、
`get_session_context`、`send_message`などとして公式チートシートにも掲載されている。

この環境で確認できるセッション操作も、一覧取得、同じセッション内へのチャット追加、
独立セッション作成、会話コンテキスト取得、メッセージ送信に対応している。
メッセージ送信は非同期の新しいターンとして届くため、実行中の相手の推論へ
即座に割り込む操作とは異なる。

### 同一セッション内の複数チャット

Agent Hostセッションでは、1つのセッション内に複数チャットを作成できる。
各チャットは履歴、タイトル、状態、エージェントまたはモデルの選択が独立している。
一方、workspaceとworktreeは共有する。

新規チャットは空の状態で始まり、別チャットの履歴を自動継承しない。
元の会話を引き継いで別案を試す場合は、新規チャットよりforkを使う。

workspaceを共有するため、チャットAが保存したファイル変更はチャットBからも
確認できる。ただし、同じファイルを同時編集すると競合、意図しない上書き、
一時的に不整合な状態を読む危険がある。並行実装では担当ファイルを分けるか、
セッションごとにGit worktreeを使う。

Agents windowでは`/btw <質問>`によるside chatも利用できる。これは元チャットの
コンテキストを非公開で引き継ぐが、メインチャットの履歴には質問と回答を追加しない。
2026年8月31日時点ではCopilotとClaudeのセッションに限られ、CodexやChat viewでは
利用できない。

### 親エージェントとサブエージェント

サブエージェントは、独立したCopilot Chat同士を対等につなぐ仕組みではなく、
親エージェントが一部の仕事を委譲する仕組みである。サブエージェントは専用の
コンテキストで動作し、結果や状態を親セッションへ返す。

Custom agentを調査担当、編集担当、レビュー担当のように定義すると、
Copilotランタイムが依頼内容に応じてサブエージェントとして選択できる。
複雑な作業を役割分担させる場合は、任意のChat同士を直接会話させるより、
この親子構造の方が管理しやすい。

### 間接的な連携

Agent Hostのセッション操作を使わない場合も、次の共有媒体で間接的に連携できる。

- `AGENTS.md`や`.github/copilot-instructions.md`で全Chatへ共通ルールを渡す
- Markdown、JSON、テスト結果などを共有ファイルとして読み書きする
- GitHub Issue、Pull Request、コミットを作業の受け渡しに使う
- MCPサーバーを介して共通のタスク管理システムへ接続する

これらはChat同士の会話ではない。共有状態を介した協調であり、更新順序、
排他制御、完了条件を別途設計する必要がある。

### 実用的な依頼例

同じAgent Hostセッション内で分担させる場合は、メインチャットへ次のように依頼する。

```text
このセッションに別チャットを2つ作成してください。
1つ目には公式ドキュメント調査、2つ目には既存コードの確認を依頼し、
両方の結果を読み取って、このチャットで結論を統合してください。
ファイル編集はメインチャットだけが行ってください。
```

別worktreeへ分離したい場合は、次のように依頼する。

```text
実装用の独立セッションをGit worktreeで作成し、対象機能を実装させてください。
完了後にそのセッションの結果と差分を確認し、このセッションへ要点を報告してください。
```

利用しているハーネスや権限にセッション操作ツールがない場合、この依頼は実行できない。
その場合は、Agents windowで人がセッションを切り替えるか、共有ファイルやIssueを
仲介させる。

### 注意点

- 独立セッションのコンテキストは自動的に漏れない。連携には明示的な読み取りや
  メッセージ送信が必要である。
- 同一worktreeでの同時編集は避け、担当範囲を分けるかworktreeで隔離する。
- 相手Chatへのメッセージは、新しいターンとして処理される。実行中処理への
  強制割り込みや共有メモリの直接書き換えとは異なる。
- サブエージェントは親へ報告する委譲構造であり、独立セッション同士の
  対等な常時会話とは異なる。
- Agents windowと複数チャットはPreviewまたは段階的提供の機能を含むため、
  バージョン、ハーネス、組織ポリシーによって利用可否が異なる。
