# アセンブリ言語の基本

## 概要

アセンブリ言語が何を表すものなのか、CPUの命令セット（ISA）や機械語との関係、基本要素、実行ファイルになるまでの流れを整理する。あわせて、x86-64とAArch64の違い、ABI（Application Binary Interface）、学習時の選び方を確認する。

## 結論

アセンブリ言語は、特定のCPUが実行できる命令を、人間が読めるニーモニックやオペランドで表した低水準の言語である。「アセンブリ言語」という単一の言語があるのではなく、x86-64、AArch64、RISC-V、マイコンなど、対象ISAごとに命令・レジスター・記法が異なる。

学習時は、最初に対象を1つに絞り、レジスター、メモリー、フラグ、分岐、スタック、関数呼び出し規約の順で理解するとよい。PC上で始めるならx86-64、組み込みやスマートフォンに関心があるならAArch64または対象マイコンのISAを選ぶのが現実的である。

アセンブリは処理の実行順序やデータの所在を細かく制御できる一方、CPUとOSの違いによる移植性の低さ、レジスターやメモリー管理の負担、保守の難しさがある。そのため、通常のアプリケーション全体をアセンブリで書くより、コンパイラー出力の理解、デバッグ、組み込みの一部、性能が重要な処理などに使うことが多い。

## 詳細

### 1. 機械語、ISA、アセンブリ言語の関係

#### 事実

- **機械語**は、CPUが命令として解釈するビット列である。
- **ISA**は、CPUが提供する命令、レジスター、データ型、メモリーアクセス、例外などのソフトウェアから見える規則である。
- **アセンブリ言語**は、ISAの命令を `MOV`、`ADD`、`LDR` のようなニーモニックで記述する表記である。
- **アセンブラー**は、アセンブリのソースを機械語を含むオブジェクトファイルへ変換する。リンカーは、複数のオブジェクトファイルやライブラリーを結合し、シンボル参照を解決して実行形式を作る。

したがって、アセンブリのソースはCPUへそのまま渡す文字列ではない。概念的には、次のような変換を経る。

```text
アセンブリソース (.s / .asm)
        |
        v
アセンブラー
        |
        v
オブジェクトファイル (.o / .obj)
        |
        v
リンカー + ライブラリー
        |
        v
実行形式
```

#### 判断

「アセンブリ言語を学ぶ」ときは、文法だけでなく、対象ISAの仕様と、OS・実行形式・ABIの仕組みを一緒に学ぶ必要がある。文法を覚えても、対象CPUや呼び出し規約が異なれば同じソースは動かない。

### 2. 主な構成要素

#### レジスター

レジスターはCPU内部にある少数の高速な記憶領域で、演算の入力、結果、アドレス、スタック位置、状態などを保持する。名前と役割はISAごとに異なる。

- x86-64: `RAX`、`RBX`、`RCX`、`RDX`、`RSP`、`RBP`、`R8`～`R15` など
- AArch64: `X0`～`X30`、`SP`、`PC` など
- 条件フラグやステータスレジスター: 演算結果がゼロか、繰り上がりがあるか、比較結果がどうかなどを保持する

#### メモリーとアドレス

プログラムの命令、データ、スタック、ヒープなどは主にメモリー上に置かれる。アセンブリでは、即値、レジスターの値、レジスターにオフセットを加えたアドレスなどを使ってデータの場所を指定する。この指定方法をアドレッシングモードという。

#### 命令

代表的な命令の分類は次のとおりである。

| 分類 | 役割の例 |
| --- | --- |
| データ転送 | レジスターとメモリーの間で値を移す |
| 算術演算 | 加算、減算、乗算、除算 |
| 論理演算 | AND、OR、XOR、ビット反転 |
| 比較・フラグ操作 | 値を比較し、条件分岐に使う状態を設定する |
| 分岐 | 条件分岐、ループ、関数呼び出し、復帰 |
| スタック操作 | 一時保存、ローカル変数、関数呼び出しの管理 |
| SIMD・浮動小数点 | 複数データの並列演算や実数演算 |

### 3. x86-64とAArch64の違い

#### 事実

- Intel 64/x86-64の命令は可変長で、命令によってバイト数が異なる。IntelのSoftware Developer's Manualは、命令の動作、エンコーディング、フラグへの影響などを命令ごとに定義している。
- AArch64のA64命令は基本的に32ビット幅で、レジスター間演算とロード・ストア命令を組み合わせる設計になっている。
- x86-64では、命令によってメモリー上の値を直接演算のオペランドにできる場合がある。
- AArch64では、一般的な演算はレジスター間で行い、メモリーとの転送は `LDR` や `STR` などのロード・ストア命令で行う。

#### 例

次の例は、どちらも「レジスターに値を置いて加算する」という概念を示したもので、完全なプログラムや特定OSの関数ではない。

```asm
; x86-64の概念例（Intel記法）
mov eax, 2
add eax, 3
```

```asm
// AArch64の概念例
mov w0, #2
add w0, w0, #3
```

実際の記法、利用できる即値、レジスター幅、命令の別名はアセンブラーとISAの版に依存する。x86系でもIntel記法とAT&T記法があり、オペランドの順序やレジスター表記が異なるため、教材やツールの記法を確認する必要がある。

#### 判断

「x86はCISC、ARMはRISC」と分類するだけでは、現代CPUの性能や内部実装までは説明できない。入門では命令形式やメモリーアクセスの違いを理解する目安として使い、実際の動作は対象ISAの仕様書で確認するのが安全である。

### 4. 関数呼び出しとABI

アセンブリ単体の命令が正しくても、Cや別のアセンブリ関数と接続するにはABIの規約に従う必要がある。ABIには、引数をどのレジスターまたはスタックへ置くか、戻り値の場所、呼び出し側・呼び出される側が保存するレジスター、スタックのアラインメント、名前修飾、例外・アンワインド情報などが含まれる。

例えばMicrosoftのx64呼び出し規約では、整数型の先頭4引数に `RCX`、`RDX`、`R8`、`R9` を使い、呼び出し側が4つのレジスター引数用のシャドースペースをスタックに確保する。これはWindows x64の規約であり、Linuxなど別のプラットフォームの規約をそのまま適用できることを意味しない。

アセンブリで関数を書く場合は、命令リファレンスだけでなく、対象OSのABIとコンパイラーが生成するコードも確認する必要がある。

### 5. コンパイラーとの関係

CやC++などのコンパイラーは、通常、ソースコードからアセンブリ、オブジェクトファイル、実行形式へ変換する。GCCでは `-S` オプションを使うと、アセンブルを行わずにアセンブリ出力を確認できる。

```text
高水準言語
   |
   | コンパイラー
   v
アセンブリ
   |
   | アセンブラー
   v
オブジェクトファイル
   |
   | リンカー
   v
実行形式
```

このため、アセンブリは「すべてを手書きするための言語」というより、コンパイラーがどのように処理を命令へ変換したかを確認するための中間表現、デバッグ・逆アセンブルの対象としても重要である。なお、最適化を有効にすると、ソースコードとの対応が分かりにくくなったり、命令の順序が変わったりする。

### 6. 用途と限界

#### 向いている用途

- マイコンの起動処理、割り込み、特殊レジスター、命令制約に関わる処理
- OSのブートコード、コンテキスト切り替え、デバイス依存の処理
- コンパイラーが生成したコードの性能やレジスター使用状況の確認
- デバッガーでのクラッシュ原因調査、逆アセンブル、リバースエンジニアリング
- 一部の暗号・SIMD処理など、対象CPUの特定命令を直接使う処理

#### 注意点

- CPU、OS、ABI、アセンブラー記法に強く依存し、移植性が低い。
- レジスターの保存、スタックの整合性、メモリーの寿命を自分で管理する範囲が広い。
- 最適化されたコンパイラー出力より常に速くなるとは限らない。
- バッファー境界、スタック破壊、保存規約違反などの不具合が重大な問題につながる。
- 命令セットの拡張やCPU世代差を考慮しないと、別の環境で実行できないことがある。

### 7. 学習の進め方

次の順序が理解しやすい。

1. 2進数、16進数、符号付き整数、ビット演算を確認する。
2. 対象をx86-64、AArch64、または使用するマイコンの1つに決める。
3. レジスター、メモリー、アドレス、エンディアン、フラグを学ぶ。
4. データ転送、算術・論理演算、比較、条件分岐、ループを小さな例で試す。
5. スタック、関数プロローグ・エピローグ、ABIを学ぶ。
6. デバッガーでレジスターとメモリーを観察し、Cのコンパイラー出力と対応付ける。
7. 最後にSIMD、割り込み、特権命令、最適化など、目的に応じた領域へ進む。

初心者が最初から複数ISAを比較すると、命令そのものの違いと記法の違いを混同しやすい。まず1つのISAで小さな処理を追い、必要になった時点で別ISAへ広げる方が効率的である。
